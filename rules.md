# System Rules and AI Guardrails

## 1. What to Use (Best Practices)
* **Pydantic Validation:** All data extracted by the `parser_node` MUST be validated through a strict Pydantic schema before moving to the `quant_node`. 
* **Python for Math (No LLM Math):** LLMs are terrible at arithmetic. The `quant_node` must NEVER attempt to calculate waterfall cash flows in its text response. It must write the logic in Python and let the `Python_REPL` tool do the math.
* **Deterministic Critic Logic:** Where possible, the `critic_node` should rely on standard Python `if/else` statements to evaluate the simulation output (e.g., `if aaa_loss > 0.0001: return False`) rather than relying entirely on LLM reasoning to decide if a test passed.
* **Explicit Tracebacks:** If the generated Python script fails, the `Python_REPL` tool must return the exact error traceback to the `quant_node` so the agent knows exactly what to fix.

## 2. What to Avoid
* **No External Data Fetching:** The generated Python code must NOT include requests to external APIs (e.g., Yahoo Finance). All simulation data (default curves, base rates) must be synthesized locally or passed into the state beforehand.
* **No Hardcoding the Extraction:** The `quant_node` must dynamically reference the JSON generated by the `parser_node`. It should not hardcode trigger values (like `121.5%`) into the script, as this breaks the flexibility of the system.
* **Avoid Infinite Loops:** Never deploy a cyclic graph without a hard cap. The LangGraph state must include an `iteration_count` variable.

## 3. Error Handling Protocols
* **Parser Hallucination Protocol:** If the `parser_node` fails to output a JSON that passes Pydantic validation (e.g., missing a required tranche), it is routed to a correction loop up to 3 times with the Pydantic validation error as the prompt.
* **Execution Failure Protocol:** If the `Python_REPL` throws a `SyntaxError`, `TypeError`, or `KeyError`, the graph routes back to the `quant_node` with the traceback, bypassing the `critic_node` entirely.
* **Max Iteration Protocol:** If `iteration_count == 5` and the `critic_node` still rejects the model, the graph terminates gracefully and returns the best-attempt code alongside a `Failed to Converge` flag.

## 4. Information Boundaries for the AI
* **Zero Assumption Rule:** The `parser_node` must only extract what is explicitly written in the PDF. If a standard fee cap is missing from the document, it must return `null` or `0`, not assume industry-standard rates.
* **Strict Role Segregation:** 
    * The *Parser* does not evaluate risk.
    * The *Quant* does not critique the legal structure; it only writes code.
    * The *Critic* does not write code; it only evaluates output and dictates changes.
* **Security Boundary:** The `Python_REPL` must be heavily sandboxed. Disable OS-level imports (`os`, `sys`, `subprocess`) in the execution environment to prevent the LLM from executing malicious commands.
